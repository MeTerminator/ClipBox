# Go 开发规范

## 基本原则

- 使用标准 Go 风格：提交前运行 `gofmt`、`go vet ./...` 和 `go test ./...`。
- 包名使用简短小写名，文件名表达职责；不使用 `util`、`helper`、`manager` 作为无法界定职责的兜底包。
- 构造函数负责建立合法对象；配置在进入业务包前完成默认值和校验。
- 错误应增加操作上下文并保留原因：`fmt.Errorf("open manifest: %w", err)`。用 `errors.Is` 判断哨兵错误，不比较错误文本。
- `context.Context` 作为可能阻塞或访问 I/O 的方法第一个参数，不存进结构体，不用 `context.Background()` 覆盖传入请求的生命周期。
- 时间统一以 UTC 持久化和比较；测试通过注入 `now` 固定时间。

## 接口与依赖

- 接口由使用方按最小能力定义。不要为每个结构体机械创建同名接口。
- `main.go` 负责选择具体实现，业务包不得读取环境变量或自行连接数据库。
- HTTP handler 只做：解析、调用、错误映射、序列化。可被 HTTP 与 WebSocket 同时调用的规则必须下沉到应用服务。
- 跨表写入、计数扣减和所有“检查后更新”操作放在仓储事务中。

## 命名与注释

- 导出标识符必须有以其名称开头的 GoDoc；包应有 `doc.go` 说明边界和不变量。
- 注释解释“为什么、约束、并发或安全不变量”，不复述代码。例如应说明为何消息先入库再广播，而不是写“保存消息”。
- 布尔值使用 `is`、`has`、`can` 等可读语义；时间使用 `...At`，时长使用 `...TTL` 或 `...Duration`。
- API 请求/响应结构留在传输包，不给数据库模型直接绑定用户输入。

## 数据库

- 所有查询使用请求上下文。
- GORM 关联加载必须显式 `Preload`；不能依赖调用方猜测关联是否存在。
- 将 `gorm.ErrRecordNotFound` 统一映射为 `store.ErrNotFound`，将唯一键冲突映射为 `store.ErrConflict`。
- 新索引和字段需同时考虑 SQLite、MySQL、旧数据回填和回滚策略。
- 大规模或破坏性迁移不得放在普通请求路径，也不能只依赖 `AutoMigrate`。

## 文件与并发

- 外部文件名只能作为展示信息和净化后的路径片段，不能直接拼接用户输入。
- 写入使用同目录临时文件、`Sync`、关闭、再 `Rename` 发布；失败时清理临时文件。
- 以 SHA-1 为键的上传会话需要持锁完成状态检查与变更；不要扩大锁范围到数据库或网络 I/O。
- 删除文件前同时检查数据库引用和目录边界。

## 测试策略

- 纯规则使用表驱动单元测试。
- 仓储测试至少覆盖 SQLite；依赖 MySQL 特性的修改必须增加对应集成测试或明确未验证。
- HTTP 测试验证状态码、响应契约和副作用；不要只断言 handler 被调用。
- 文件测试使用 `t.TempDir()`；时间和随机碰撞路径应可控。
- 修复缺陷时先增加能复现问题的回归测试。

本仓库的推荐检查命令：

```bash
gofmt -w main.go internal/*/*.go
go vet ./...
go test ./...
cd frontend && npm run typecheck && npm run build
```

在受限环境中 Go 默认缓存不可写时，可使用：

```bash
GOCACHE=/tmp/clipbox-go-cache go test ./...
```

## 提交约定

每个提交只表达一个意图，推荐使用 `feat:`、`fix:`、`refactor:`、`test:`、`docs:` 前缀。结构移动与行为修改尽量拆开，便于审查和回滚。提交前检查 `git diff --check`，不得提交数据库、上传文件、密钥、`.env` 或构建缓存。
